KEY FILES EXPLAINED
═══════════════════

🔧 server.js (Backend Server)
   ───────────────────────────────
   • Runs on port 3000 (configurable via PORT env var)
   • Manages chat rooms using Map data structure
   • Stores user connections and messages
   • Broadcasts messages to room members
   • Handles user join/leave events
   • Auto-deletes empty rooms after 1 hour

   Key functions:
   - generateRoomId()      : Creates 8-char room codes
   - generateAvatar()      : Color-codes users
   - io.on('connection')   : WebSocket connection handler
   - io.on('send-message'): Message broadcasting


🌐 public/index.html (Home Page)
   ──────────────────────────────────
   • First page users see at http://localhost:3000
   • Two main options:
     1. Create New Chat Room
     2. Join existing by room code
   • Beautiful gradient design
   • Responsive on mobile and desktop
   • Input validation and error handling


💬 public/chat.html (Chat Interface)
   ──────────────────────────────────
   • Accessed via /chat?room=ROOMCODE
   • Main chat interface
   • Features:
     - Message display with timestamps
     - User list (right sidebar)
     - Real-time message input
     - Typing indicators
     - Join/leave notifications
     - Copy room code button
     - Auto-scroll to latest message

DATA FLOW
════════════

HOME PAGE FLOW:
  User visits http://localhost:3000
  │
  ├─→ Click "Create Room"
  │   └─→ POST /api/rooms
  │       └─→ Server generates room ID
  │           └─→ Redirect to /chat?room=ROOMID
  │
  └─→ Enter room code & click Join
      └─→ Redirect to /chat?room=ROOMID


CHAT ROOM FLOW:
  User arrives at /chat?room=ROOMID
  │
  ├─→ Socket.IO connection established
  │
  ├─→ emit 'join-room' event
  │   └─→ Server:
  │       ├─ Verifies room exists
  │       ├─ Generates username
  │       ├─ Adds user to room
  │       └─ Sends message history & user list
  │
  ├─→ User sends message
  │   └─→ emit 'send-message'
  │       └─→ Server:
  │           ├─ Creates message object
  │           ├─ Saves to room
  │           └─ Broadcasts to all users
  │
  └─→ User closes window
      └─→ 'disconnect' event
          └─→ Server:
              ├─ Removes user from room
              ├─ Broadcasts 'user-left' event
              └─ Marks room for cleanup

PERFORMANCE CHARACTERISTICS
════════════════════════════

Message Delivery: ~10-50ms (local network)
Concurrent Users: 100+ per process
Memory per Room: ~1-10KB (depending on message count)
Memory per User: ~40KB connection overhead
Message Size: Typically 100-500 bytes
Latency: Sub-100ms with WebSocket
